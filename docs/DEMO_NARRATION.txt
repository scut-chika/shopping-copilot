HOW TO USE THIS FILE

==== BLOCK 1 — opening, about 22 seconds ====
[ on screen: the score table from tools/record.py ]

A customer says: I'm looking for tunics, but I'm still exploring. Fifty thousand
products. Ten turns to put the one they want into your top ten.

The organizer's baseline manages that twelve percent of the time, and burns
almost all ten turns doing it. This finds it every time, in about two turns,
ranked first in one hundred ninety four sessions out of two hundred.


==== BLOCK 2 — the live session, about 58 seconds ====
[ on screen: the turn-by-turn session. Hold on the one-item list. ]

A real session. The agent has never seen the target.

Turn one. It has nothing but a category, so five hundred and thirty four
products are still consistent. Watch what it does not do. It does not fill ten
slots to improve its odds. It shows one product, its best guess, and asks.

That is where most of the score comes from. The evaluator ends the session the
moment the target appears, at whatever rank it landed on. So getting lucky on
turn one at rank eight is not a win. It locks in rank eight forever, and throws
away the turn that would have made it rank one. Waiting costs two percent of
efficiency and buys up to thirty percent of ranking. Thirteen to one.

Turn two. The candidates collapse to three, and the one it puts up is right.
Rank one, turn two.


==== BLOCK 3 — where the score comes from, about 35 seconds ====
[ on screen: the ablation table ]

We assumed the clever part would be retrieval. It isn't.

Every customer sentence is built, word for word, from the target's own catalog
record. So the right index is not a vector store. It is an inverted index, from
what the customer said back to the products that could have said it.

Turn that off and the score barely moves. Turn off the question policy and a
third of the score disappears. Turn off the refusal to answer while still
guessing, and six more points go with it.


==== BLOCK 4 — the honest part, about 38 seconds ====
[ on screen: the generalization table ]

A perfect hit rate on two hundred sessions is a warning sign, not a victory lap.
At the ceiling, that set cannot tell you anything. You are only fitting it.

So we built our own. Eight hundred sessions over products that appear nowhere in
the public set. Then again with a second seed.

Zero point nine three, both times, against zero point nine seven on the public
set. So the honest number for data it has never seen is zero point nine three.
We would rather say that than let the public figure be read as a forecast.


==== BLOCK 5 — offline, about 22 seconds ====
[ on screen: the cost table, then the repo URL ]

Final scoring may run with the network disabled. So the scored configuration has
no model in it. No API, no credentials, no third party dependency. Zero tokens,
zero dollars, sixty six milliseconds a turn.

There is an optional language model stage, for reading paraphrased customers. We
measured it against a real model, and switched it off.

And that is not a README claim. One test starts a fresh interpreter and fails if
that module is so much as imported.

Shopping Copilot. Two turns instead of ten.
